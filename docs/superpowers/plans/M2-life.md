# M2 Life Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Read `docs/superpowers/plans/README.md` (constraints, contract, layout) first. Steps use `- [ ]`.

**Goal:** The scene feels alive: a local train crosses a level crossing on a schedule, a village with stream and bridge fills the east/west, and a couple sits on the bench under the hero tree.
**Architecture:** Four independent features under `src/features/`, all deterministic from `ctx.time.elapsed`. The train timetable is a pure module in `src/shared/train-schedule.ts` (shared by the train and railway features, since features never import each other). Colliders are registered through `ctx.colliders`; heights come from `ctx.terrain`.
**Tech Stack:** three (pinned in M0), Vitest. Shaders as `.glsl` with `?raw`.
**Spec:** `docs/superpowers/specs/2026-11-07-sakura-relax-design.md` §2 (intent only; do not read unless stuck).

## Global Constraints
See README "Global constraints". Additionally for M2: read exact field names of `LAYOUT` in `src/core/layout.ts` (this plan uses logical names: `LAYOUT.crossing {x,z}`, `LAYOUT.railway {z, xMin, xMax}`, `LAYOUT.train {cars, carLength, speed, period, xMin, xMax}`); never hardcode numbers that exist there. Rail head height constant `RAIL_TOP = 0.42` m above `ctx.terrain.heightAt(x, railwayZ)` is shared by railway and train (duplicated by value, documented in both feature READMEs). Characters face +z when `root.rotation.y = 0` (M1 convention). Register features in `src/features/index.ts` in this order: railway, train, village, couple.

## Review Focus
1. Schedule at the period boundary (t = 75) or a large `elapsed` jump emits `train:approach` twice or not at all (test in T2 `events.test.ts`).
2. Crossing stuck closed/open if a `train:clear` is missed (tab hidden, frame stall) → state must be derived from the schedule every frame, not from events (test in T1 `crossing.test.ts`).
3. House / lantern / torii colliders overlapping the dirt path or the stream, trapping the player (test in T3 `placement.test.ts`).
4. Stream water z-fighting with terrain, and a gap in stream colliders next to the bridge (tests in T3 `stream.test.ts`).
5. Missing head bone in a character rig crashes the couple update loop (test in T4 `head.test.ts`).

### Task M2-T2: Train schedule and train
**Model:** sonnet · **Type:** feature-logic · **Size:** M · **Depends:** none
**Files:** Create `src/shared/train-schedule.ts`, `src/shared/train-schedule.test.ts`, `src/features/train/{index.ts,events.ts,events.test.ts,model.ts,README.md}`; Modify `src/features/index.ts`.
**Interfaces:**
- Consumes: `LAYOUT.train`, `LAYOUT.crossing`, `LAYOUT.railway`, `ctx.terrain.heightAt`, `ctx.time.elapsed`, `ctx.bus`, `createToonMaterial`, `PALETTE.trainBody/trainStripe`.
- Produces (`train-schedule.ts`, pure, no three): `TrainCfg = { cars, carLength, speed, period, xMin, xMax, startOffset }`, `TRAIN_CFG` (from LAYOUT.train incl. `startOffset`; every function evaluates the timetable at `t + cfg.startOffset`, and `runEvents` times are returned in elapsed coordinates, i.e. minus `startOffset`; schedule is also consumed by audio and intro); `trainStateAt(t: number, cfg = TRAIN_CFG): { active: boolean; direction: 1 | -1; frontX: number; run: number }` (run = floor(max(t,0)/period); direction = run even ? 1 : -1; local = t − run·period; frontX = direction=1 ? xMin + speed·local : xMax − speed·local; active = speed·local ≤ (xMax − xMin) + cars·carLength); `runEvents(run: number, crossingX: number, cfg = TRAIN_CFG): { tApproach, tClose, tPass, tClear, tOpen }` (tPass = front reaches crossingX; tApproach = tPass − 10; tClose = tPass − 8; tClear = tail past `crossingX ± 4`, i.e. dir +1: front ≥ crossingX + 4 + train length, dir −1: front ≤ crossingX − 4 − train length; tOpen = tClear + 3; all absolute seconds incl. `run·period`); `crossingClosed(t: number, crossingX: number, cfg = TRAIN_CFG): boolean` (= tClose ≤ t < tOpen for run floor(t/period)).
- Produces (`events.ts`): `class TrainEventTracker { constructor(crossingX: number, cfg?: TrainCfg); advance(t: number): { type: 'approach' | 'pass' | 'clear'; direction: 1 | -1; eta: number }[] }` — keeps per-run emitted flags, emits in order, handles jumps, eta = max(0, tPass − t) at emit time (0 for pass/clear).
- [ ] Tests first (`train-schedule.test.ts`, all with `cfg = { ...TRAIN_CFG, startOffset: 0 }` unless stated): `trainStateAt(0)` toEqual `{active:true,direction:1,frontX:-400,run:0}`; `trainStateAt(410/14).frontX` ≈ 10; `trainStateAt(75)` → direction −1, frontX 400, run 1; `trainStateAt(150).direction === 1`; `trainStateAt(61).active === true`, `trainStateAt(61.5).active === false`; `trainStateAt(-5)` equals `trainStateAt(0)`; `runEvents(0,10)` → tApproach ≈ 19.2857, tClose ≈ 21.2857, tPass ≈ 29.2857, tClear ≈ 33.4286, tOpen ≈ 36.4286; `runEvents(1,10).tPass` ≈ 102.857 and `.tClear` ≈ 107; `trainStateAt(0)` with the real `TRAIN_CFG` equals `trainStateAt(startOffset, zeroOffsetCfg)`; `crossingClosed`: false at 21.2, true at 21.3, true at 36.4, false at 36.5, true at 100.
- [ ] Tests first (`events.test.ts`, `startOffset: 0` cfg): stepping t from 0 to 200 in dt = 1/60 yields exactly 9 events (3 runs × approach, pass, clear) in time order, each approach `eta` in (9.9, 10]; stepping with dt = 0.1 gives the same sequence; `advance(74.999)` then `advance(75.001)` emits nothing new (no duplicate approach, run 1 approach not yet due); a single `advance(0)` then `advance(100)` emits run 0's three events then run 1's approach (eta 0 ≤ … clamp ok); calling `advance` twice with the same t emits nothing the second time.
- [ ] Implement schedule + tracker. Run → green.
- [ ] `model.ts`: `buildTrain(cfg): { group: THREE.Group; cars: THREE.Group[] }` — 3 cars, each 18 × 3.3 × 2.9 m `RoundedBoxGeometry` (radius 0.35) body in `trainBody`, a 0.45 m stripe band in `trainStripe` along both sides at sill height, grey roof slab, 7 emissive window panels per side (`#ffe9b0`, `MeshBasicMaterial`), 2 bogies per car (dark box + 4 wheel cylinders). Long axis = x. Share geometries/materials across cars (no per-car clones).
- [ ] `index.ts`: each frame `s = trainStateAt(ctx.time.elapsed)`; group visible = `s.active`; car i centre x = `frontX − direction·carLength·(i + 0.5)`; y = `heightAt(x, railwayZ) + RAIL_TOP`; z = railway z; `rotation.y = direction === 1 ? 0 : Math.PI`; sway: `rotation.z = 0.004·sin(elapsed·1.7 + i)`, `position.y += 0.01·sin(elapsed·3.1 + i)`. Emit events returned by `tracker.advance(elapsed)` as `train:approach {direction, eta}`, `train:pass {direction}`, `train:clear {direction}`. No colliders (fences block). `dispose` removes meshes/geometries.
- [ ] Append to `features/index.ts`; commit; PR; screenshot of train at the crossing (set `elapsed` via debug if needed).

**Interfaces:**
- Consumes: `LAYOUT.railway`, `LAYOUT.fences`, `LAYOUT.crossing`, `ctx.terrain`, `ctx.colliders`, `ctx.time.elapsed`, `ctx.bus.emit('crossing:state')`, `crossingClosed` from `src/shared/train-schedule.ts`.
