# M3 Walk Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Read `docs/superpowers/plans/README.md` (constraints, contract, layout) first. Steps use `- [ ]`.

**Goal:** The visitor can walk around the scene on desktop and phone: third-person player, orbit camera, touch controls, and petals that kick up around the feet.
**Architecture:** Four features under `src/features/` (`player`, `camera`, `touch-controls`, plus edits inside `petals`). They communicate only through `WorldContext` (`ctx.player`, `ctx.input`, `ctx.camera`, `ctx.colliders`, `ctx.terrain`, `ctx.mode`). Pure math lives in testable modules (`motion.ts`, `cameraMath.ts`, `gestures.ts`, `kick.ts`).
**Tech Stack:** three, Vitest, Playwright, nipplejs (pinned in T3).
**Spec:** `docs/superpowers/specs/2026-11-07-sakura-relax-design.md` §2 (intent only; do not read unless stuck).

## Global Constraints
See README "Global constraints". Additionally for M3: **no `src/core/types.ts` change** (`InputState.touch: TouchSink` with `move(x, y, run)`, `look`, `zoom`, `action` already exists from M0). Conventions used by all four tasks: camera yaw `θ` is defined by the camera's horizontal forward `f = (−sin θ, −cos θ)` (θ = 0 looks toward −z, north), so `θ = atan2(−f.x, −f.z)`; player `heading h` is the facing direction `(sin h, cos h)` (h = 0 faces +z, spawn heading = π faces north); the camera is "behind" the player when `θ = π − h`. Register in `src/features/index.ts` in this order, after all M1/M2 features: `player`, `camera`, `touch-controls`. Constants: player radius 0.35 m, `STEP_WALK = 0.55 s`, `STEP_RUN = 0.35 s`.

## Review Focus
1. Player tunnels through a thin fence/hedge at run speed with dt = 0.1 (test in T1 `player.test.ts`).
2. Player escapes the bounds at a corner where two hedge boxes meet, sliding through the seam (test in T1 `player.test.ts`).
3. Camera clips into the hero tree trunk when the player stands on the far side (test in T2 `cameraMath.test.ts`).
4. Pointer lock lost or refused (Esc, tab switch, iframe policy) → look stops, no unhandled rejection or console error (test in T2 `pointerlock.test.ts`).
5. Joystick stays "pressed" after `touchcancel`, `orientationchange`, tab hide or a mode change, so the player walks forever (tests in T3 `gestures.test.ts`, `joystick.test.ts`, and e2e in T5).

### Task M3-T2: Third-person camera
**Model:** opus · **Type:** feature-logic · **Size:** M · **Depends:** none (reads `ctx.player` only)
**Files:** Create `src/features/camera/{index.ts,cameraMath.ts,cameraMath.test.ts,pointerlock.ts,pointerlock.test.ts,README.md}`; Modify `src/features/index.ts`.
**Interfaces:**
- Consumes: `ctx.input.{look,zoom}`, `ctx.player.position`, `ctx.camera`, `ctx.terrain.heightAt`, `ctx.colliders.resolve`, `ctx.mode`, `ctx.bus` (`game:mode`), `renderer.domElement`.
- Produces (pure, `cameraMath.ts`): constants `SENS = 0.0025`, `PITCH_MIN = −0.35`, `PITCH_MAX = 0.9`, `DIST_MIN = 2.5`, `DIST_MAX = 9`, `DIST_DEFAULT = 5`, `TARGET_Y = 1.5`, `GROUND_MARGIN = 0.4`; `applyLook(yaw, pitch, dx, dy): { yaw; pitch }` (`yaw −= dx·SENS`, `pitch += dy·SENS`, clamped); `applyZoom(dist, zoom): number` (`dist + zoom·0.01`, clamped; positive zoom = wheel down = farther); `orbitOffset(yaw, pitch, dist): { x; y; z }` = `(sin yaw·cos pitch, sin pitch, cos yaw·cos pitch)·dist`; `groundClamp(y, groundH): number` = `max(y, groundH + 0.4)`; `pullIn(maxDist, blockedAt: (d: number) => boolean, step = 0.25, margin = 0.3, minDist = 1.2): number` (scan d from `step` to `maxDist`; at first blocked d return `max(minDist, d − margin)`); `smoothDistance(cur, target, dt): number` (pull-in uses rate 20, release rate 3, `cur + (target − cur)·(1 − exp(−rate·dt))`); `behindYaw(heading) = π − heading`.
- Produces (`pointerlock.ts`): `requestLock(el: HTMLElement): void` (calls `el.requestPointerLock?.()`; if it returns a promise, attaches `.catch(() => {})`; wraps in try/catch), `shouldLock(env: { mode: GameMode; coarse: boolean; locked: boolean }): boolean` (= mode 'play' && !coarse && !locked).
- Behaviour decisions: acts only in `'play'`; in `'intro'` (M5 owns the camera) and `'photo'`/`'menu'` it does nothing and keeps whatever transform exists. On `game:mode` → `'play'` it sets `yaw = behindYaw(player.heading)`, `pitch = 0.25`, `dist = DIST_DEFAULT` and then eases the camera position toward the orbit position (position damping `1 − exp(−8·dt)`; look-at target = `player.position + (0, TARGET_Y, 0)`), so intro → play blends without a cut. Resume from `'photo'` keeps previous yaw/pitch/dist.
- [ ] Tests first (`cameraMath.test.ts`): `applyLook(0,0,100,0).yaw` ≈ −0.25; `applyLook(0,0,0,1000).pitch === 0.9`; `applyLook(0,0,0,−1000).pitch === −0.35`; `applyZoom(5, 100) === 6`, `applyZoom(5, 1e5) === 9`, `applyZoom(5, −1e5) === 2.5`; `orbitOffset(0,0,5)` → `(0,0,5)`, `orbitOffset(π/2,0,5)` → `(5,0,0)` (±1e-9) and its length is always `dist`; `groundClamp(0.1, 0) === 0.4`; `pullIn(5, () => false) === 5`; `pullIn(5, d => d >= 3) === 2.7`; `pullIn(5, d => d >= 0.5) === 1.2`; `smoothDistance(5, 2, 0.1)` closer to 2 than `smoothDistance(2, 5, 0.1)` is to 5; **hero tree clipping:** with `createColliders()` holding circle `(0,0,0.8)`, player at (0, 0, −2.5), yaw 0, pitch 0.2, a `blockedAt` built from `resolve(point, 0.25)` moving the point > 0.01 → `pullIn(5, …) ≤ 1.5` and ≥ 1.2; same with player at (0, 0, 2.5) yaw 0 (camera on the open side) → 5.
- [ ] Tests first (`pointerlock.test.ts`): fake element whose `requestPointerLock` returns `Promise.reject(new Error('denied'))` → `requestLock` neither throws nor leaves an unhandled rejection (listen on `process.on('unhandledRejection')` for one tick); element without `requestPointerLock` → no throw; element that throws synchronously → no throw; `shouldLock({mode:'play',coarse:false,locked:false}) === true`, `coarse: true` → false, `mode: 'intro'` → false, `locked: true` → false.
- [ ] Implement: `init` registers a `click` on the canvas → `if (shouldLock(...)) requestLock(canvas)` and a `pointerlockchange` listener that only tracks `locked` (no throw, no state corruption when lock is lost: look simply stops arriving). `update(dt)` in play: `applyLook` with `ctx.input.look` (core already resets it per frame), `applyZoom` with `ctx.input.zoom`, desired position = target + `orbitOffset`; `blockedAt(d)` samples the point at distance `d` along the orbit direction and calls `ctx.colliders.resolve(p.clone(), 0.25)`; distance via `pullIn` + `smoothDistance`; ground: `y = groundClamp(y, heightAt(x, z))`; `camera.position.lerp`; `camera.lookAt(target)`.
